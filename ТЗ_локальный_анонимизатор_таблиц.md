## 1. Название и цель

- **Название:** «Локальный анонимизатор таблиц данных» (Local Table Anonymizer).
- **Тип:** настольное приложение, работа ТИМ (только инструменты и методы, без ИИ).
- **Цель:**
  - заменять персональные данные (ПДн) в таблицах на обратимые обезличенные коды;
  - позволять работать с анонимными данными (аналитика, сводные, выгрузки);
  - полностью восстанавливать ПДн в переработанной таблице.
- **Ключевой принцип:** анонимизация — **биективное** преобразование (1 значение = 1 код), обратимое через зашифрованный словарь соответствий.

## 2. Обязательные гарантии безопасности

- **Г-1. Ноль сетевых вызовов.** Приложение не выполняет ни одного обращения в сеть (нет обновлений, телеметрии, аналитики, CDN). Подтверждается **статическим анализом** исходников и сборки + динамическим тестом при отключённой сети.
- **Г-2. Маппинг всегда зашифрован.** Словарь «код ↔ значение» хранится только в зашифрованном виде (AES-256-GCM, ключ — из пароля через PBKDF2). Открытым текстом не сохраняется нигде.
- **Г-3. Потеря пароля = безвозвратная потеря маппинга.** Пароль хранится только как хеш (для проверки), восстановить его невозможно; дублей словаря в открытом виде не существует. Осознанное ограничение, предупреждается при создании проекта.
- **Г-4. Биективные коды.** Одно исходное значение → ровно один код; разные значения → разные коды. Гарантирует корректность обратного преобразования.
- **Г-5. Нейросети не используются.** Детект ПДн — детерминированные правила (имена колонок → regex → статистика), никаких ML-фреймворков в зависимостях.
- **Г-6. Исходники не изменяются.** Все результаты — в новых файлах; исходный файл побайтово не меняется.

## 3. Стек (рекомендация курса)

- **Язык:** Python 3.11+.
- **GUI:** **PyQt6** — кросс-платформенность, богатая экосистема, лёгкая упаковка в exe.
- **Таблицы:** `pandas` + `openpyxl` (XLSX), `xlrd` (XLS), встроенный `csv` (CSV).
- **Криптография:** `cryptography` — AES-256-GCM; `hashlib` — PBKDF2-HMAC-SHA256, **600 000 итераций**, соль 16 байт.
- **Хранилище проекта:** SQLite (`sqlite3` из стандарт-либа).
- **Сборка:** PyInstaller (one-file / one-dir, без сети при установке и запуске).
- **Запрещено:** `requests`, `httpx`, `urllib` (исходящие вызовы), `torch`, `tensorflow`, `transformers` и прочие ML-пакеты — проверяется автотестом.

## 4. Поддержка форматов

| Формат | Чтение | Запись | Примечание |
|---|---|---|---|
| CSV | ✅ | ✅ | разделители `;` `,` `\t`; кодировки UTF-8, UTF-8-BOM, Windows-1251 |

## 5. Архитектура

- **4-уровневая схема:** `GUI → Application → Domain → Infrastructure`.
- **Правило зависимости:** каждый уровень знает только соседний ниже; `Domain` не знает ни о GUI, ни о файловой системе, ни о сети.
- **Ядро (Domain):** детерминированный движок на **HMAC-SHA256** (генерация кодов) + **AES-256-GCM** (шифрование маппингов).

### Ключевые компоненты

| Компонент | Назначение |
|---|---|
| `ColumnDetector` | 3-уровневый детект PII: имена колонок → regex → статистика |
| `MappingEngine` | HMAC-SHA256 для генерации детерминированных кодов |
| `CryptoLayer` | AES-256-GCM + PBKDF2 (600K итераций) для шифрования маппингов |
| `TableTransformer` | Замена ячеек на индексы и обратно |

### Структура проекта

```
project/
  src/
    gui/              # PyQt6: окна, мастера, диалоги
    application/      # сценарии (Use Cases): анонимизация, восстановление, статистика
    domain/           # ColumnDetector, MappingEngine, CryptoLayer, TableTransformer
    infrastructure/   # io_tables (CSV/XLSX/XLS/JSON/SQLite), mapping_store (SQLite), journal
  tests/              # юнит- и интеграционные тесты, тесты безопасности
  build/              # артефакты PyInstaller
  docs/               # руководство пользователя
  main.py             # точка входа
```

## 6. Спецификация файлов проекта

```
Проекты/<имя_проекта>/
  project.db          — SQLite: таблица mapping (index, value_enc, value_hash, column_type)
                       value_enc — персональное значение, зашифрованное AES-256-GCM
                       value_hash — HMAC-SHA256(нормализованное значение, ключ проекта)
  project.meta.json   — версия, дата, соль KDF, формат кодов (не секретно)
  journal.log         — журнал операций: время, действие, файл, число строк (без ПДн)
```

- **Имена выходных файлов:** `исходный__anon.xlsx` (анонимная копия), `исходный__restored.xlsx` (восстановленная копия).
- **Формат кодов:** `ID-000001`; по типам столбцов — префиксы `PH-` (телефон), `EM-` (e-mail), `DOC-` (документ), `BD-` (дата рождения).

## 7. Диаграммы потоков

### П-1. Анонимизация

```
Файл (CSV/XLSX/XLS/JSON/SQLite)
        │
        ▼
ColumnDetector: предложение столбцов ПДн (имена колонок → regex → статистика)
        │  (пользователь подтверждает/правит выбор)
        ▼
TableTransformer ── для каждого значения: нормализация → HMAC-SHA256 (есть в словаре?)
        │                      │да                    │нет
        │                      ▼                      ▼
        │              выдать существующий    выдать новый код, сохранить
        │              код                     value_enc=AES(value), value_hash
        ▼
Запись анонимной копии + сохранение project.db (зашифрован) + journal.log
```

### П-2. Деанонимизация (восстановление)

```
Переработанная таблица + пароль
        │
        ▼
CryptoLayer: PBKDF2(пароль) → ключ → расшифровка маппинга (при неверном пароле — отказ)
        │
        ▼
Обратный индекс index → value в памяти; сопоставление столбцов по заголовкам/формату
        │
        ▼
TableTransformer: замена кодов на ПДн; неизвестные коды — по политике (оставить/пусто/исключить)
        │
        ▼
Запись восстановленной копии (исходник не перезаписывается) + журнал; память очищается
```

## 8. Функциональные требования (тезисы)

- **F-1. Импорт:** мастер пошаговый — Файл → Предпросмотр (50 строк) → Столбцы и типы ПДн (ФИО, Телефон, E-mail, Адрес, Номер документа, Дата рождения, Свободный текст) → Итоги. Auto-детект от `ColumnDetector`, решение — за пользователем.
- **F-2. Анонимизация:** биективная замена по словарю; одинаковые значения → одинаковый код (в рамках проекта); разные проекты → разная нумерация (таблицы нельзя сопоставить между собой); пропуски не трогаются; неотмеченные столбцы сохраняются (в них работают формулы/сводные); подозрительные столбцы помечаются предупреждением, но не меняются автоматически.
- **F-3. Работа с анонимными данными:** файл — обычный, открывается в Excel/Любой программе; встроенная статистика (число строк, уникальных кодов, пропусков) без раскрытия ПДн.
- **F-4. Восстановление:** после ввода пароля; сопоставление столбцов автоматически + вручную; неизвестные коды — политика (оставить/пусто/исключить, по умолчанию «оставить» с предупреждением); результат в новый файл.
- **F-5. Управление проектом:** список проектов; просмотр словаря только после пароля (значения скрыты по умолчанию); экспорт словаря — **зашифрованный по умолчанию, открытый формат только после подтверждения (диалог предупреждения)**; импорт словаря; ручные соответствия до обработки; удаление проекта с безопасной очисткой.
- **F-6. Журнал:** метаданные операций без ПДн и паролей; просмотр в интерфейсе.
- **F-7. Безопасность:** пароль ≥ 8 символов; хранится только хеш PBKDF2 (600K); авто-закрытие проекта по таймауту (30 мин); права администратора не запрашиваются.

## 10. Тест-кейсы (входные критерии)

- **Т-1. Статический анализ:** сбор/поиск в коде и в дистрибутиве импортов `socket`, `http`, `requests`, `urllib`, `torch`, `tensorflow` → 0 совпадений.
- **Т-2. Офлайн-прогон:** все сценарии на машине с отключённой сетью (контроль трафика) → 0 пакетов, всё работает.
- **Т-3. Round-trip:** 10 000 строк × 10 столбцов ПДн → анонимизация → восстановление → сравнение → 100 % совпадений (регистр, пробелы, спецсимволы, эмодзи, кириллица).
- **Т-4. Границы:** пустой файл; 1 столбец; дубликаты; пропуски; разделитель-запятая внутри значений; BOM; кодировка 1251 → без падений, понятные ошибки.
- **Т-5. Пароль:** копия project.db + попытка чтения без пароля / с неверным паролем → маппинг нечитаем.
- **Т-6. Неизменность исходника:** хеш исходного файла до/после → совпадает.
- **Т-7. Удаление проекта:** файлы маппинга перезаписаны/удалены → восстановление невозможно.
- **Т-8. Производительность:** 100 000 × 100 ≤ 30 с.
- **Т-9. Детерминизм/биективность:** повторная анонимизация в одном проекте → те же коды; в разных проектах → разные; коллизии кодов отсутствуют.
- **Т-10. Неизвестные коды:** код, отсутствующий в маппинге → срабатывает политика, выводится предупреждение.
